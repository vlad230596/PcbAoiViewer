# PcbAoiViewer — notes for agents

Project goal, stage status, results, rationale and roadmap live in `README.md` (Russian). Read it before changing the stitcher or picking the next stage.

## Working here

- Python: uv. `uv sync` (add `--group legacy` for the old pipeline), run scripts with `uv run <script>.py`; Python 3.13 (`.python-version`). Keep OpenCV 4.x (5 has no `AKAZE_create`) and rapidocr 1.2.x (1.4 reads differently). scipy is not a dependency; numpy least squares is enough so far.
- Current pipeline: `GridStitcher.py` (algorithm), `stitchGrid.py` (CLI), `BuildViewer.py` (Deep Zoom tiles + `index.html`, stack viewer + `3d.html`). Multi-height: `FocusStack.py` (algorithm), `stackFocus.py` (CLI) — reference height stitched by `GridStitcher`, every other height mapped onto it by one similarity, depth from focus, ortho-corrected second pass, all-in-focus. Old pipeline (`main.py`, `MainStitcher.py`, `PlaneStitcher.py`, `ViewDrawer.py`, `Dataset.py`, `test.py`) is history; leave it untouched.
- Board data: `importBoard.py <artifacts.zip>` (registry server export) -> `boards/<project>-r<rev>/board.json` + `export/` + `datasheets/` (git-ignored). Modules `Ipc2581.py` (server's parser, keep in sync — its snake_case names stay as on the server on purpose, so fixes copy both ways), `AltiumExport.py`, `Components.py`, `Datasheets.py`, `BoardData.py` are stdlib only. Coordinates: mm from IPC-2581 Datum, Y up, top view, bottom not mirrored.
- Board on the panorama: `alignBoard.py out/<name> boards/<board>` fits board mm -> panorama px (coarse edge match over rotation x mirror, then RANSAC affine on drilled holes; pads are useless, solder hides their edges) and writes `out/<name>/board.json` + `datasheets/`; `index.html` shows it as the "Board (CAD)" layer. Check `align_crops/` by eye after a change.
- Markings: `markingSheets.py out/<name>` (contact sheets of `parts/` crops, designators only) -> reading into `out/<name>/markings.json` (no local OCR engine; read by a vision model so far) -> `markingCheck.py out/<name>` (resistor codes vs BOM, presence vs fit) -> `ocrMarkings.py out/<name>` (RapidOCR second reading + `marking_img/` reading images; weak on 0603 dot-matrix codes). `rapidocr_onnxruntime` models are bundled in the wheel. `BuildViewer.py out/<name>` re-renders `index.html` without re-stitching.
- Resistor codes: `ResistorCodes.py` (numpy/OpenCV recognizer: body by R-B, top-hat glyphs, proportional-font cuts, HOG + per-class kNN with an upside-down reject class, code grammar, orientation-bar prior) trained on `dataset/resistor_codes/` (tracked; `resistorDataset.py add [--auto]|correct|synth|stats`; `--auto` labels only where reference and Qwen agree, else `review.csv`; synthetic glyphs from `SynthGlyphs.py`, training only) -> `readResistorCodes.py out/<name>` writes `parts[ref].resistorCode` (leave-one-out), `--eval` for the step table (~69 % per part on one board). `cv2.ROTATE_90_CLOCKWISE == 0`: test the angle, not the rotate code.
- VLM second reading: `vlmMarkings.py out/<name>` (project env) runs `vlmWorker.py` (self-contained, no project imports) as a subprocess in a separate torch venv (`--python` / `AOI_VLM_PYTHON`, default `research/ocr_engines/venvs/gpu`, weights in `research/ocr_engines/cache/hf`, offline) -> `parts[ref].vlm`. Never put BOM values into the prompt. Keep torch out of the project `.venv/` and `pyproject.toml`.
- IC marking from source views: `cutMarkingViews.py out/<name> --stack out/stack [--sheets]` (`MarkingViews.py`; the stack must be built at `--scale 1` from the same reference stitch) cuts the body out of every frame x sharpest height -> `marking_views/` + `marking_views.json`; `vlmMarkings.py out/<name> --views` reads them in 4 turns and votes -> `parts[ref].vlmViews`. The viewing angle, not the height, decides whether laser marking shows; image measures do not pick the right view, so the readings vote. Don't name a CLI like its module with another case: Windows sees one file. Stack page with the board: `BuildViewer.py out/stack --board out/captured_51.5`, serve `out/` (paths go `../captured_51.5/`); its "floors" row fuses any set of heights per tile in the browser (`focusz.bin`), "part tops" draws the views into the outlines.
- STEP model + photo: `stepToMesh.py` (CAD venv `research/cad/venv` = `pip install cadquery-ocp numpy`, OCP 8: static `_s` methods, `OCP.collections.Sequence_TDF_Label`, keep the XCAF document referenced or the tree reads empty; keep OCP out of `.venv/` and `pyproject.toml`) -> `boards/<board>/model/`; `texturedModel.py out/stack --board boards/<board> [--align out/captured_51.5]` (`CadTexture.py`; STEP mm = IPC-2581 Datum, uv through the alignBoard M + parallax correction for heights the ortho pass missed) -> `model.glb` + `model_tex*.jpg` + `model.html` (serve `out/stack` over http). Walls get the part's photo top colour; side faces are not photographed.
- CAD height reference: `compareCad.py out/stack --board boards/<board> [--align out/captured_51.5]` (`CadReference.py`) rasterizes `model/mesh.npz` (STEP frame == IPC-2581 Datum, z = 0 board top; top-side, fitted, present parts) as max-z top view onto the depth cells via `align.M`, fits a residual XY shift, writes `out/stack/cad/` (error maps, per-part table, crops) and re-renders `3d.html` (CAD / error textures, CAD surface, overlay). The stack is blind above Z max - board (~3.8 mm).
- Outputs go to `out/` (git-ignored). Datasets (`SocketTester2/`, `captured*`) are git-ignored and large; read only.
- Code style: camelCase methods, small classes, thresholds given in full-resolution px and scaled by `self.scale` inside `GridStitcher`.
- Quick iteration: `--scale 0.5 --no-viewer --seam-crops 0` runs in ~15 s; full resolution ~30 s.
- Stack: `stackFocus.py "SocketTester2/captured_*" --ref 51.5 --scale 0.5 --no-viewer` ~4 min; `--ortho-passes 0` halves it when only the depth matters.

## Verifying a change

Numbers alone miss seam artefacts. After a stitching change, crop the panorama at full resolution on seams over text and IC pins, on both tantalum capacitors and the 220-16 capacitor pair, and on the red connectors, then look at the crops. Compare against the previous output folder. `report.json` holds residual stats and timings.

For the focus stack, crop the same places in `focus.jpg` (all-in-focus) and `layers/z*.jpg`, look at `height_color.png`, and open `3d.html` in a browser. For the marking layer, compare IC tops in `marking.jpg` against `focus.jpg` (the QFN under frame 50_60 is the hard case) and check `marking.json` for the chosen frames.

## Gotchas

- Off-board background (the mat) lies at another depth: its pairs disagree by 50–175 px and are rejected on purpose (`--max-deviation`). Parallax regions there are expected.
- Z is camera height (focus plane moves up with it); camera ~89.6 mm above the board. `captured_45.0..49.5` were shot at another XY offset and focus below the board; the stack uses Z ≥ 50.
- The camera is rotated ~47° to the machine axes, so diagonal grid neighbours overlap strongly and are real pairs.
- In legacy `Dataset.at(row, col)` "row" is machine X and Y is inverted.
- `capture.py` (old rig, dearpygui) is history; capture with `captureGrid.py` (Ender-3 V3 SE, Marlin, CH340 COM3/COM4, camera MSMF MJPG 1920x1080 max). It never homes and never moves Z without `--z`; every motion needs the user's OK for now. Z has no endstop (`z_min` always reads TRIGGERED): never send bare `G28` or `G28 Z`. `G28 X`/`G28 Y` first lift Z to 10.
- Open the printer port with DTR off: a DTR edge resets the board and loses the homing.
- Camera "gives no frames" (MSMF 0x80070006 / 0xC00D3704) usually means another app holds it (Windows Camera).
- New rig: microscope ~75 mm to +X of the nozzle; ~40 px/mm, frame ~48 x 27 mm, camera ~3° to the machine axes; head +X moves the image up, +Y moves it left. Board centre at head ~X64 Y130 (first test board).
